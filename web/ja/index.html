無料の Blender Extension · 4.2 以降

.unitypackage をマテリアルごとBlender へ。

パッケージをビューポートにドラッグ＆ドロップするだけ。アーマチュアとシェイプキー付きのメッシュが入り、テクスチャが展開され、Unity 側のマテリアル設定が Blender のノードとして組み直されます。Unity プロジェクトは要りません。

アドオンは Unity と同じ手順でパッケージを読み、Blender が実際に使えるものだけを組み立てます。対応付けできない値もカスタムプロパティに保存するので、情報は失われません。

メッシュ

FBX / OBJ / glTF / VRM / Collada のモデルを、アーマチュアとシェイプキー付きのまま読み込みます。同梱の .blend も、明示的に有効にしたときだけアペンドできます。

  • 新しい FBX インポーターがあれば優先
  • VRM は VRM アドオンがあればそちらに委譲
  • パッケージごとに 1 つのコレクション

マテリアル

各 .mat をメッシュに対応付け、シェーダープロファイルを通して Toon ノードグループか Principled BSDF に変換します。影色、MatCap、リムライト、エミッション、アルファが引き継がれます。

  • .meta、名前、prefab のスロットの順で対応付け
  • prefab が .mat を差し替えている場合はスロット単位で分割
  • 元パッケージ無しで、後から別モードに再構築可能

テクスチャ

マテリアルが参照する画像だけを、.blend の隣かアドオンのキャッシュに展開します。.blend にパックすることも、参照されていないマスクやアイコンを一緒に読み込むこともできます。

  • Cutout / Transparent の設定を引き継ぎ
  • ノーマルマップやマスクは Non-Color で読み込み
  • 書き出す前にサイズ上限と空き容量を確認

仕組み

2 段階で、推測しない

Unity のシェーダーと Blender のノードは 1 対 1 に対応しないので、直接変換はしません。

  1. 1パッケージを 1 度だけ読む。tar.gz を索引化し、必要な GUID だけを展開します。YAML はアドオン専用のパーサーがメモリ上で読みます。
  2. 2マテリアルを正規化する。シェーダープロファイルが生の .mat プロパティを、シェーダーに依存しない記述（色、マップ、影、MatCap、リム、アルファ）に変換します。
  3. 3ノードを組む。その記述から Toon グループか Principled のツリーを作ります。記述自体もマテリアルに保存されるので、パッケージ無しで別モードに再構築できます。
導入

3 ステップ。以後の更新は自動で届く

このサイトを Extension Repository として 1 度登録すれば、Blender がアドオンを一覧に出し、更新も管理してくれます。

リポジトリを追加

Blender で 編集 > プリファレンス > エクステンション入手 > リポジトリ を開き、+ から リモートリポジトリを追加 を選んで、この URL を貼り付けます。

{{BASE_URL}}/index.json

Extension をインストール

エクステンション入手で Unity Package Importer を検索してインストールします。ファイルから入れたい場合は バージョン {{VERSION}} の zip をダウンロードし、「ディスクからインストール」を使います。

パッケージをドロップ

.unitypackage を 3D ビューポートにドラッグ＆ドロップするか、ファイル > インポート > Unity Package を選びます。ポップアップでオプションを調整してインポート。複数ファイルを一度にドロップしても構いません。

各オプションの既定値はアドオンのプリファレンスで変えられます。サイドバー（N キー）の「Unity Package」タブに、読み込んだ内容、マテリアルごとの解決結果、警告が表示されます。

安全性

自分で作っていないパッケージを開くために

アバターはいろいろな人の手を経て届きます。アドオンはすべてのパッケージを信頼できない入力として扱います。

パッケージ内のコードは一切実行しない

C# スクリプト、シェーダー、その他のアセットは無視します。ディスクに書き出すのはモデルファイルと、マテリアルが参照するテクスチャだけ。.mat / .meta / .prefab はテキストとしてメモリ上で解析します。

同梱の .blend は既定で開かない

.blend は、Auto Run が有効なときに Blender が実行する Python を含めます。他人のパッケージの .blend をアペンドするのは、インポートごとの明示的な選択で、ドキュメントにも記載しています。

アーカイブ処理は堅牢化済み

パスを検証し、シンボリックリンクは辿らず、大きすぎるメタデータは無視し、展開する合計サイズを上限と空き容量に対して書き出し前に確認します。

Blender が解析する部分は Blender が守る

FBX、glTF、画像のデコードは Blender 自身が行います。Blender は最新の LTS に保ち、出所不明のパッケージは別のインストールやサンドボックスで開いてください。

範囲

読み込まないもの

目的は Blender で正しく見えるメッシュであって、Blender の中に Unity プロジェクトを作ることではありません。次のものは Unity 側に残ります。

  • シェーダー本体（マテリアルは変換しますが、シェーダーは変換しません）
  • C# スクリプトとコンポーネント
  • アニメーションと Animator Controller
  • prefab の階層（prefab はマテリアル割り当ての参照にだけ使います）
  • VRChat の Expression メニューとパラメーター
  • 物理、コライダー、揺れもの
