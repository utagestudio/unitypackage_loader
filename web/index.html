What comes through

Everything worth keeping, in one import

The add-on reads the package like Unity would, then rebuilds what Blender can actually use. What it cannot map is kept as custom properties so nothing is lost.

Meshes

FBX, OBJ, glTF, VRM and Collada models, with armatures and shape keys intact. Bundled .blend files can be appended too, but only when you opt in.

  • New FBX importer preferred when available
  • VRM handed to the VRM add-on if installed
  • One Collection per package

Materials

Each .mat is matched to its mesh, then converted through a shader profile into a Toon node group or a Principled BSDF. Shadow color, MatCap, rim light, emission and alpha survive the trip.

  • Matched via .meta, name, or prefab slot
  • Per-slot split when a prefab reassigns .mat files
  • Rebuild in another mode later, without the package

Textures

Only the images a material references are extracted, next to your .blend or into the add-on cache. Pack them into the file if you prefer, or pull in unreferenced masks and icons as well.

  • Cutout and transparent modes carried over
  • Non-color data for normal and mask maps
  • Size guard before anything is written

How it works

Two stages, no guesswork

Unity shaders and Blender nodes do not map one to one, so the add-on never converts directly.

  1. 1Read the package once. The tar.gz is indexed, then only the GUIDs you need are extracted. YAML is parsed by the add-on's own reader, in memory.
  2. 2Normalize the material. A shader profile turns raw .mat properties into a shader-independent description: colors, maps, shadow, MatCap, rim, alpha.
  3. 3Build the nodes. That description becomes a Toon group or Principled tree. It is also stored on the material, so you can rebuild in another mode without the package.
Install

Three steps, then updates arrive on their own

Register this site as an extension repository once. Blender lists the add-on and keeps it up to date.

Add the repository

In Blender, open Edit > Preferences > Get Extensions > Repositories, click +, choose Add Remote Repository and paste this URL.

{{BASE_URL}}/index.json

Install the extension

Search for Unity Package Importer in Get Extensions and click Install. Prefer a file? Download version {{VERSION}} as a zip and use "Install from Disk".

Drop a package

Drag a .unitypackage onto the 3D Viewport, or use File > Import > Unity Package. Adjust the options in the popup and click Import. Several files at once are fine.

Defaults for every option live in the add-on preferences. The "Unity Package" tab in the sidebar (N key) shows what was imported, how each material was resolved, and any warnings.

Security

Built to open packages you did not make

Avatars come from many hands. The add-on treats every package as untrusted input.

No code from the package ever runs

C# scripts, shaders and other assets are ignored. Only model files and the textures a material references are written to disk. Material, meta and prefab files are parsed in memory as text.

Bundled .blend files stay closed by default

A .blend can carry Python that Blender runs when Auto Run is on. Appending one from a stranger's package is opt-in, per import, and documented.

Archive handling is hardened

Paths are validated, symbolic links are never followed, oversized metadata is ignored, and the total size is checked against a limit and the free disk space before anything is written.

What Blender parses, Blender must protect

FBX, glTF and image decoding are done by Blender itself. Keep Blender on the latest LTS, and open packages from unknown sources in a separate installation or a sandbox.

The full notes are in the README.

Scope

What is not imported

The goal is a mesh that looks right in Blender, not a Unity project inside Blender. These stay on the Unity side.

  • Shader source code (materials are converted, shaders are not)
  • C# scripts and components
  • Animations and animator controllers
  • Prefab hierarchies (prefabs are read only for material assignment)
  • VRChat Expression menus and parameters
  • Physics, colliders and dynamic bones
