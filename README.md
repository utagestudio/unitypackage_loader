# Unitypackage Importer for Blender

English | [日本語](README_ja.md) | [Website](https://utagestudio.github.io/unitypackage_loader/) | [GitHub](https://github.com/utagestudio/unitypackage_loader)

Developed by [UTAGE.STUDIO](https://utage.studio/)

A Blender Extension that imports `.unitypackage` files directly from File > Import, placing meshes
(including armatures and shape keys) with the material settings and textures from the Unity side applied.

- Supported Blender: 4.5 or later (developed on 5.2 LTS, tested on 4.5 LTS and 5.2 LTS)
- What is imported: FBX / OBJ / glTF / VRM / Collada (Blender 4.5 only; removed in Blender 5.0) / bundled .blend files (opt-in), `.mat` files (lilToon / MToon / Poiyomi / Standard / URP / HDRP / VRChat Mobile (Quest) shaders; others on a best-effort basis using generic rules), referenced textures, and animation as actions on muted NLA tracks: the animation takes inside models (split into Unity's clips; motion-only FBX files with the same skeleton are merged into one armature) and Generic animation clips (`.anim`: blend shapes, object visibility and transforms)
- What is not imported: shader source code, C# scripts, Humanoid animation clips, animation curves on bones, Animator Controllers, Expression menus, etc. Prefab hierarchies, lights and cameras are reproduced only when a scene is imported.
- VRM: when the [VRM format](https://extensions.blender.org/add-ons/vrm/) add-on is installed, `.vrm` models are handed to it (MToon materials, humanoid rig, spring bones and expressions are reproduced by the add-on). Without it, the glTF importer is used and materials are rebuilt from the bundled `.mat` files.

## Installation

There are three sources and they all ship the same extension. **Install from only one of them** (see "Switching sources" below).

**extensions.blender.org (recommended)**

The extension is listed on Blender's official extensions platform:
[Unitypackage Importer](https://extensions.blender.org/add-ons/unitypackage-loader/).
In Blender, open Preferences > Get Extensions, search for "Unitypackage" and click Install.
New versions show up as updates in Blender.

**Register the GitHub Pages Extension Repository**

The same extension is also distributed via GitHub Pages. In Blender, open Preferences > Get Extensions > Repositories,
click "+", choose "Add Remote Repository", and register the following URL. You can then install and update
the extension from the list, and new versions show up as updates in Blender.

```
https://utagestudio.github.io/unitypackage_loader/index.json
```

The [same page](https://utagestudio.github.io/unitypackage_loader/) (the URL without `index.json`) shows the registration URL and a link to the zip.

**Install from a zip**

Drag the zip from the website onto the Blender window, or load it with "Install from Disk" in the menu at the
upper right of Preferences > Get Extensions. Installed this way, the extension is not updated automatically.
The same zip is also available for free on [BOOTH](https://utagestudio.booth.pm/items/8910607), with optional support versions that contain the same file.

**Switching sources**

Blender treats each source (repository) as a separate extension. If the add-on is installed from two sources, both
are enabled and override each other's features, so it stops working correctly. To switch, uninstall the current copy
in Preferences > Get Extensions first, then install from the new source. Preferences are stored per source and are
not carried over.

**During development (use the repository directly)**

```sh
ln -s "$PWD/unitypackage_loader" ~/.config/blender/5.2/extensions/user_default/unitypackage_loader
```

In Blender, open Preferences > Get Extensions, run "Refresh Local" from the menu in the upper right,
and enable "Unitypackage Importer". Uninstall any copy from another source first.

Build the distribution zip with:

```sh
blender --command extension build --source-dir unitypackage_loader --output-dir dist
```

The website and the Extension Repository are generated by `.github/workflows/pages.yml` on every push to main
(it runs Blender's `extension build` and `extension server-generate` in CI). Once, on first setup, set the
repository's Settings > Pages > Source to "GitHub Actions".

## Usage

- **Drag and drop**: drop a `.unitypackage` onto the 3D Viewport to open a popup with import options. Multiple files can be dropped at once.
- **Menu**: choose File > Import > Unitypackage (.unitypackage), pick the file in the file browser, adjust the options on the right as needed, and click Import.

The options show Material Mode and Scale; everything else is folded into the Model / Materials / Textures sections.

| Section | Option | Description |
|---|---|---|
| (always shown) | Material Mode | `Auto` (Toon for toon-style shaders, Principled for PBR) / `Principled BSDF` / `Toon (Node Group)` / `Unlit (Emission)` / `Names Only` |
| | Scale | Scale passed to the model importer |
| Model | FBX Importer | Prefer the new C++ importer (`Auto`) / choose explicitly |
| | Animation | `Muted` (default): import the models' animation takes and the package's `.anim` clips as muted NLA tracks / `Active`: the same, but unmute the first track of each object / `None`: do not import animation. See [Animation clips](#animation-clips) |
| | Ignore Leaf Bones | Passed to the FBX importer (default ON) |
| | VRM via VRM Add-on | Import `.vrm` with the VRM format add-on when installed (default ON); otherwise fall back to the glTF importer and rebuild materials from `.mat` |
| | Import Bundled .blend Files | Append objects from `.blend` files inside the package (default OFF). See [Security notes](#security-notes) |
| Materials | Force Opaque | Ignore Unity's Cutout / Transparent settings |
| | Backface Culling | Hide back faces where Unity's `_Cull` setting does (off by default: every material is drawn on both sides). After import, "Backface Culling On / Off" in the sidebar's Tools panel switches it for the materials of the selected meshes |
| | Normal Maps / Emission | Whether to apply each element |
| | Outlines (Solidify) | Add a Solidify outline from Unity's outline color and width (converted with Width Scale) |
| | Reuse Existing Materials | Reuse a material with the same name if one already exists instead of rebuilding it |
| | Bundled .blend Materials | `Keep` (default) / `Rebuild` materials from bundled .blend files (only when the option above is on) |
| | Store Unity Properties | Store GUIDs, shadow colors, etc. as custom properties |
| Textures | Extract To | `Beside .blend` (`//textures/<package name>/`) / `Add-on Cache` / `Custom Path` |
| | Pack Into .blend | Pack images into the .blend file |
| | Import Unreferenced Images | Also load every other image in the package (masks, icons, textures of materials the imported items don't use) as image data. When off, only the textures of the materials actually assigned are extracted and loaded |

A summary appears in the Info bar. The "UPI" tab in the 3D View sidebar (N key) shows counts,
per-material resolution status, and warnings. The system console prints details (the matched .mat for each
material, textures used, and warnings). A Collection named after the package is created and the objects are placed in it.
Armature objects are displayed as wire (Object > Viewport Display > Display As) so that they don't cover the meshes.

### Choosing what to import

Packages that only bundle other `.unitypackage` files (one per render pipeline, such as `BuiltIn.unitypackage` and
`URP.unitypackage`, with no models, prefabs or scenes outside) first open a dialog to choose the one to import. The chosen
package is written to the extract folder and imported together with the meshes and textures of the outer package.

When the package has more than one scene, prefab or model to choose from, a selection dialog opens after the options.
Choose the unit at the top, then tick what to import in the list. In Scenes only the first importable scene is ticked
by default, since importing several scenes at once tends to overlap buildings and lights (Prefabs and Models are all
ticked):

- **Scenes**: imports what a scene (`.unity`) places, at the positions, rotations and scales set in Unity. Each scene
  gets its own Collection; the GameObjects above the models are recreated as Empties, and inactive objects are hidden.
  Only the scene's contents are imported. Copies of the same model with the same materials share their mesh data.
  Small props copied side by side under a common parent in Unity (for example several cups in a room) are placed one by one.
  Parts of a model file that a prefab or the scene does not use (for example unused LODs, extra nodes, the other
  pieces of a model file that bundles many props, or parts a prefab or the scene removed from a model) are not imported, matched by the mesh each Unity renderer references
  (turn off **Unused Parts** in the dialog to import them hidden instead). Where Unity has an LODGroup, only the most
  detailed level (LOD0) stays visible: the distant levels are imported and hidden (toggle this with **LODs** in the
  dialog; the hidden objects stay in the file and keep their level in the `unity_lod` custom property). Objects imported from model files keep their FBX node name in the `unity_fbx_node` custom property (Blender adds a numeric suffix when an object with the same name already exists).
  Renderers set to cast shadows only in Unity (Cast Shadows: Shadows Only) become objects that the camera does not see
  but that still cast shadows, drawn as wireframe in the viewport (Scenes and Prefabs).
  Lights and cameras are imported too (toggle them with "Also Import"): light intensity is converted from values
  measured in Unity (Built-in and URP) and Blender's EEVEE, and the original values are kept as custom properties.
  The render pipeline is detected from the URP / HDRP additional data on lights and cameras, and from the materials'
  shaders. For HDRP scenes, the lights are scaled by the Volume's exposure (toggle it with **Exposure** in the dialog;
  automatic exposure is approximated with its upper limit). The Blender scene's exposure (Color Management) is left
  unchanged, so scenes from different pipelines can be mixed in one Blender scene.
  Lights that only affect lightmaps in Unity (baked and area lights) become real-time lights and are listed in the
  warnings. Unity's built-in meshes (Cube, Sphere, Capsule, Cylinder, Plane and Quad, such as a Quad laid as the
  ground) are rebuilt with the same shape, size and UVs and get their assigned materials. Renderers that use a Unity
  Mesh asset instead of a model file (a `.asset`, or a mesh embedded in a prefab by tools such as UModeler) are built
  from that mesh too, also with the Prefabs unit. URP / HDRP Decal
  Projectors (graffiti, stains, posters) become flat planes with the decal material made semi-transparent, placed in
  the middle of each projector's box (toggle it with **Decals** in the dialog). Decals on flat walls and roads look
  close to Unity; decals spread over uneven ground or around corners, the draw order and normal-only decals are
  approximations. A Decal Projector whose material is not a decal shader is not drawn in Unity either, so it is skipped
  and counted in the warnings. Unity Terrains become meshes built from the heightmap, with a material that blends the layers'
  textures (diffuse, normal and mask) by the alphamaps. A fine heightmap is thinned out to the number of vertices per
  side chosen with Terrain under "Also Import" in the dialog (129, 257, 513, 1025 or full; 513 by default), and holes
  are left open. Scenes that hold only a Terrain and no models can be imported too. Terrain trees and grass are not
  imported and are counted in the warnings. UI and other
  meshes that are not in the package are not imported and are reported as warnings. For a model file (FBX) placed directly, the position of its root is read. Changes to
  objects inside it (materials, positions of parts such as open doors) are applied when the model's `.meta` is in the
  format of Unity 2018.2 and earlier, which has a name table; otherwise they are counted in the warnings.
- **Prefabs**: imports each prefab with its own material assignments, in its own Collection inside the package Collection.
  Color variants that share a model can be imported together. When two or more prefabs are selected, **Arrange** places
  them `Side by Side` (next to each other without overlapping, wrapping into a grid when there are many) or
  `Stack at Origin`. Prefabs with an LODGroup hide their distant LOD levels, and parts of a model file that the prefab
  does not use are not imported, as in scenes. Parts under an inactive GameObject in the prefab and parts with a disabled
  renderer are imported hidden.
- **Models**: imports the model files (FBX etc.) as they are. Materials are resolved as described in
  [Matching meshes to materials](#matching-meshes-to-materials). Model files that prefabs use only for collision
  (MeshCollider) and never display are marked `collider only` and are unticked by default (they stay in the list, so
  you can tick them to import them).

One import uses one unit, so the same model is not imported twice by accident. Items that cannot be imported stay in
the list, greyed out with the reason (for example `no mesh in package` or `.blend import disabled`). The dialog
remembers the unit and the arrangement chosen last. With the Prefabs unit, the layout inside a prefab (positions,
rotations and scales of its child objects, and several placements of the same model) is reproduced in the same way as
in scenes, with the prefab's root at the origin of its Collection.

Defaults can be changed in Preferences (Edit > Preferences > Add-ons > Unitypackage Importer), including whether the
selection dialog opens (`Selection Dialog`: `Ask` / `All Models` / `First Model Only`) and `Arrange Prefabs`.
You can also register an additional GUID table for custom shaders (a JSON file in the same format as `shader_guids.json`).
"Max Extract Size" (default 8 GiB, 0 = no limit) refuses an import before writing anything when the files to extract
from one package would exceed it or the free space of the destination.
To stay within the Windows path length limit, files whose full path would be too long are placed in short folders under
`_long/` in the destination. If the destination folder itself is too long, the import stops with an error; in that case set
Textures > Extract To to `Custom Path` and choose a short folder such as `C:\upi`.

### Animation clips

Animation is added as **muted** NLA tracks named after each clip, so the scene looks the same right after the import.
To preview a clip, unmute its track in the NLA editor (or click its star to solo it), or select the strip and press Tab to
edit the action. With Animation set to `Active`, the first track of each object is unmuted instead (only one, because
unmuted NLA tracks override each other).

#### Motions inside models

Animation takes inside FBX files (for example motion packs, or `model@motion.fbx` files) are split into the clips that the
model's `.meta` defines in Unity (Model Import Settings > Animation: name, first and last frame). All clips of a take share
one action, and each strip plays its own frame range. Models without clip settings get one clip per take. Short clips
(0.1 seconds or shorter, such as a T-pose take) are skipped, and the active action that the FBX importer assigns is cleared.

When several motion-only models (no meshes, one armature) share the same skeleton, they are merged into one armature
that has all the motions as NLA tracks (Models only). An FBX without a skin uses its default pose as the rest pose, so
the rest pose differs from file to file; the keys are converted so that each motion keeps its pose on the remaining
armature. A skeleton that lacks some bones (for example weapon bones) is merged too; the missing bones stay at rest.
When a scene places the same model many times, the actions of its takes are shared.

#### Generic `.anim` clips

Generic animation clips (`.anim`) in the package become one action per clip. These curves are read:

- Blend shape weights (`blendShape.<name>`, 0–100 in Unity) → shape key values (0–1)
- GameObject active state (`m_IsActive`) and Renderer `m_Enabled` → `hide_viewport` / `hide_render` (deactivating a GameObject also hides its children)
- Transform position, rotation (quaternion or Euler) and scale → the object's location, rotation and scale, sampled every frame

A clip does not say which model it belongs to, so the importer looks for the imported object under which the most curve
paths resolve, and treats it as the object the clip is played on (all placements of the same model get the clip).
Each clip gets an NLA track on every object or shape key it animates. Keys start at the scene's start frame and use the scene's frame rate.
Looping clips get a Cycles modifier on their F-curves.

Clips that only switch a state are skipped: clips whose values never change, or that end within 0.1 seconds. Unity's
Animator uses such clips as states and makes the motion with transitions (outfit toggles and expressions of VRChat avatars,
the steering angle of a vehicle, and so on), so they have nothing to play back in Blender.

Not imported (the report lists how many were skipped): state clips (above), Humanoid clips (the body motion is stored as muscle curves, so the whole clip is skipped, including its other curves; the original motion is usually in an FBX in the package, which is imported as above),
curves on bones, clips that only animate the object they are played on (no path, so the object is unknown), and curves on
materials or object references. Clips whose paths match no imported object are skipped too. Animator Controllers are not read.

### Security notes

- **Bundled .blend files are not imported by default.** A `.blend` can carry Python code (driver expressions,
  registered text blocks) that Blender runs when "Auto Run Python Scripts" is enabled, so appending a `.blend` from
  an untrusted package is equivalent to running its scripts. Turn on "Import Bundled .blend Files" only for packages
  you trust, and keep "Auto Run Python Scripts" off unless you need it.
- **The add-on itself never executes code from the package.** C# scripts, shaders, Python and other assets are ignored.
  Only the following are extracted to disk or read: model files (`.fbx` `.obj` `.gltf` `.glb` `.vrm` `.dae`, and `.blend`
  only with the option above), the textures of the materials assigned to what you import (every image with "Import Unreferenced Images"),
  the `.mtl` next to an `.obj` and the `.bin` next to a `.gltf`. `.mat`, `.meta` and `.prefab` files are parsed in memory
  with the add-on's own readers (Unity YAML text, or Unity's binary serialized format) and never written out.
- **Parsing the model and image files is done by Blender itself**, not by this add-on: FBX / OBJ / glTF / Collada by
  Blender's importers, and PNG / TIFF / TGA / EXR / PSD etc. by its image libraries (OpenImageIO and friends).
  A crafted file that targets a bug in those components cannot be blocked here. Keep Blender on the latest LTS release,
  and open packages from unknown sources in an isolated environment (a virtual machine, a sandbox, or a separate Blender
  installation without other add-ons).
- Archive handling is hardened against common tricks: paths are validated (no `..`, absolute paths, drive letters,
  reserved device names or control characters), symbolic links are never followed while extracting, oversized metadata
  is ignored, and the total size to extract is checked against "Max Extract Size" and the free disk space before writing.

### Matching meshes to materials

Materials are resolved in this order:

1. The "material name → .mat" entries in the model's `.meta` (ModelImporter externalObjects)
2. A `.mat` with a matching name (if several share the name, the one closest to the model's folder wins)
3. The .mat held for the same submesh by the Renderer of a GameObject with the same name inside a prefab

Materials that match none of these are left as the importer created them and are reported as warnings.

What Unity actually renders is the material set on a prefab's Renderer, so when a prefab assigns a .mat, it takes
precedence over steps 1 and 2. For packages where the FBX shares a small number of materials and the prefab assigns
a different .mat per part on the Unity side, Blender materials are split per slot following the prefab's assignments.
When the model itself has no materials at all, a slot is created from the prefab's assignment and filled.
A prefab's Renderers are applied only to the model whose mesh they reference, so objects with the same name in
another model are not affected. With the Models unit, when several prefabs use the same model (for example, color
variants), their assignments are merged, with the first one by path taking precedence; to use a specific prefab's
assignments, import that prefab with the Prefabs unit. Material overrides in Prefab Variants and nested prefabs are read when the source is a prefab in
the package; overrides applied directly to a model (FBX) instance are applied when a scene is imported and the model's
`.meta` is in the Unity 2018.2-and-earlier format (which has a name table). Without a name table, material overrides are
matched to the imported objects by their names and hierarchy (Unity derives the internal IDs from them). Visibility overrides
and removals of parts inside such a model are matched the same way: deactivated parts and disabled renderers are hidden, and
removed parts are treated like unused parts (Scenes and Prefabs). Objects whose names are not unique inside the model cannot be
matched; those overrides, and position overrides on parts inside such a model, are reported as a warning.
A prefab lists its materials in Unity's submesh order (the order in which the mesh's polygons first use each material),
which can differ from Blender's slot order, so the entries are matched to slots in that order.

Selecting multiple `.unitypackage` files in the file browser imports them in one batch (one Collection per package,
every model with the Models unit, without the selection dialog).

### Material conversion policy

Unity shaders and Blender nodes do not map 1:1, so conversion happens in two stages:
`.mat` → a shader-independent intermediate representation → Blender nodes.

- **Toon (Node Group)**: the `UnityToon` node group reproduces shadow color (border, blur, strength), MatCap (Normal / Add / Screen / Multiply),
  rim light, emission, and alpha. It uses Shader to RGB for lighting, so it is intended for EEVEE (no shading in Cycles).
- **Principled BSDF**: connects base color, normal, emission, and Metallic / Roughness. The specular color of URP's
  specular workflow and Simple Lit, and of HDRP's Specular Color, is approximated with IOR and Specular Tint. HDRP's
  mask map is wired into Metallic and Roughness with its remap ranges applied.
- **Unlit (Emission)**: the simplest setup, wiring the texture straight into Emission with no lighting.

There are dedicated rules for lilToon / Poiyomi / MToon / VRChat Mobile, Built-in Standard, URP (Lit / Complex Lit /
Simple Lit / Unlit / Baked Lit) and HDRP (Lit / the first layer of LayeredLit / Unlit); other shaders are read from
common property names. A material whose shader was switched can keep the previous shader's settings, so URP and HDRP
materials are read only by that pipeline's names. When the shader's source (a Shader Graph or `.shader`) is in the
package, settings the shader does not declare are ignored (the shader's logic itself is not interpreted, so shaders
that build their color from custom names may come in white). When a Shader Graph sets a texture's tiling inside the
graph (a Tiling And Offset node driven by a material value), the node connections are followed and that value is used
as the texture's tiling / offset (only for textures read with the first UV set; graph-specific blending such as mask
images is not reproduced).

The intermediate representation itself is stored in the custom property `unity_normalized` (JSON), and values not used by
Blender are stored in `unity_props`. "Rebuild in Another Mode" in the sidebar's Tools panel rebuilds the materials of the
selected meshes in a different mode without the original package; its options (Force Opaque and so on) start from the
settings used at import (or the last rebuild). Outlines can be added and removed from the same panel.

## Development

```sh
# Unit tests (no bpy required)
python3 -m unittest discover -s tests -t .

# Integration tests with the synthetic packages (no real assets required). tests/integration_runs.json lists
# which generator builds each package and which expectations run against it (CI uses the same list).
# Missing packages are generated first, and a pass/fail summary is printed at the end.
python3 tests/run_integration.py                  # every expectation file (packages go to _local/unitypackages/)
python3 tests/run_integration.py --generate       # rebuild the synthetic packages first (after changing a generator)
python3 tests/run_integration.py --only scene     # only expectation files whose name contains "scene"

# A single package with a single expectation file
blender -b --factory-startup --python tests/integration_import.py -- _local/unitypackages/synthetic_multi.unitypackage tests/expectations_synthetic.json

# Integration test with a real package on your machine (package in _local/unitypackages/, expectations.json in _local/)
blender -b --factory-startup --python tests/integration_import.py
```

Pull requests and pushes to main / release branches run `.github/workflows/tests.yml`: the unit tests on Python 3.11 and 3.13
(the versions bundled with Blender 4.5 and 5.2), and the integration tests with the synthetic packages on Blender 4.5 LTS and 5.2 LTS.

Test data (unitypackage files, extracted contents, expected values) goes in `_local/` (packages themselves in `_local/unitypackages/`). This directory is gitignored,
and the data of the assets used for testing is never committed (the committed test data is synthetic only).
See `tests/expectations.schema.md` for the file format.

See [DESIGN.md](DESIGN.md) for design details.

## Directory layout

```
unitypackage_loader/         The Extension itself
  blender_manifest.toml
  core/                      bpy-independent: package index, Unity YAML / binary readers, .meta, material normalization
                             and shader profiles, mesh-to-material mapping, prefab / scene expansion and placement,
                             lights, exposure, decals, built-in meshes, terrains
  blender/                   bpy-dependent: import flow, model import, materials and nodes, textures, scene objects
                             and placement, terrains, toon node group, outlines
  operators/                 File > Import, the selection dialog, rebuilding materials, outlines
  ui/                        Preferences and the "UPI" sidebar panel
tests/                       Unit tests, integration tests, synthetic package generation
tools/                       Website build, screenshots and image sources for the listings
web/                         Website source (English index.html, Japanese ja/, assets/)
```
